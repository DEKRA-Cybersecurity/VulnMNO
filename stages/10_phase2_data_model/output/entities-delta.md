# Data model — Phase 2 delta

## Scope

Four new entities + three column additions on existing Phase-1 tables. SQLAlchemy models committed in-place into `04_api_build/output/backend/app/models/`. Alembic migration `0002_phase2` autogenerated against the running Phase-1 schema (`0001_initial`). Seed loader `app/seed_phase2.py` is idempotent and additive — it does not touch any Phase-1 row.

- `../09_phase2_contract/output/admin-endpoints.md` (entity needs for admin portal)
- `../09_phase2_contract/output/loyalty-endpoints.md` (loyalty schema)
- `../09_phase2_contract/output/adapter-interfaces.md` (gateway result fields → columns)
- `../03_data_model/references/entity-rules.md` (conventions reused unchanged)

## Open questions

- **`AdminSession` table:** intentionally NOT added. Sessions use Starlette signed cookies — no DB row, no per-session revocation. If Phase 3 needs "kick a specific admin out", introduce `admin_sessions` then; reflected as `OUT-OF-PHASE-2` in the requirements backlog.
- **Loyalty redemption:** model fields (`reason='redemption'`) are forward-compatible but not used in Phase 2.
